# Mathburst bidirectional semantic editing design

**Status:** Approved in conversation on 2026-09-01  
**Scope:** Rebuild Mathburst editing, native tools, WebMCP coverage, mathematical widgets, and in-product animation. Do not create the submission video in this phase.  
**Delivery style:** Hackathon-simple implementation, deterministic demo behavior, no CI/CD, and no automated test suite.

## Supersession

This document supersedes earlier Mathburst design decisions where they conflict with this specification. In particular:

- projects are isolated object graphs, not camera bookmarks inside one shared world;
- the new plain project and scene names replace the earlier cinematic names;
- full WebMCP coverage can increase the previous count of 18 tools;
- native editable objects replace forced template creation;
- the semantic kernel and animation timeline become product architecture.

## Product thesis

Mathburst must behave as a mathematical editor, not as a gallery of frozen demonstrations.

Every visible mathematical object must support **bidirectional semantic editing**. The user or an agent can edit the symbolic form, numerical values, direct visual handles, or linked controls. Each edit updates every other view of the same mathematical state.

For example, one semantic expression can have an equation view, a graph, a value table, parameter sliders, a vertex handle, and an animation track. Editing any one of these views updates the shared expression and all other views.

The same system must support human actions and WebMCP actions. A later video can replay deterministic WebMCP calls that construct complex scenes from an empty canvas. The replay is scripted for reliability, but every call and resulting object is real.

## Approved design decisions

The conversation established these decisions:

1. Use a hybrid architecture: shared semantic primitives form the base, while specialized widgets remain editable presets.
2. Use deterministic named handles for direct edits. When a graph drag is ambiguous, show candidate edits with live previews.
3. Keep derived geometry points locked. Users must edit their parents or explicitly detach them.
4. The AI composes native Mathburst objects through declarative WebMCP tools. It does not generate or execute JavaScript.
5. Use semantic WebMCP batches that expand into visible primitive construction steps.
6. Use a progressive inspector: inline handles for fast edits, a compact bottom inspector on selection, and an expandable advanced editor.
7. Put each geometry construction inside a geometry-canvas object. Its internal primitives keep stable IDs and full WebMCP coverage.
8. Store mathematical expressions independently from their visual views. Equation, graph, table, and control views can share one expression.
9. Put animation in an optional Animate mode. Humans and agents edit the same timeline data.
10. Make the later agent demo an instrumented construction: semantic calls visibly unfold into native points, lines, formulas, constraints, and animation tracks.

- Arbitrary JavaScript generated by an agent.
- A general computer-algebra system or unrestricted symbolic inverse solver.
- A complete replacement for GeoGebra, Mathematica, Blender, or Manim.

- Submission-video capture, narration, editing, rendering, or deployment.

## Architecture

### Semantic kernel

The semantic kernel is the source of mathematical truth. It stores entities that do not depend on a specific renderer:

- expressions and expression parameters;
- scalar, vector, and matrix variables;
- constraints and dependency edges;
- geometry constructions and primitives;
- data series and computed values;
- widget bindings;
- animation timelines and tracks.

Visible objects become editable views over these entities:

- equation view;
- graph view;
- value table;
- parameter control;
- geometry viewport;
- matrix grid;
- vector plane;
- 3D viewport;
- text or label view;
- specialized mathematical panel.

One entity can have several views. A view stores layout and presentation data. It does not duplicate the canonical mathematical value.

### Binding graph

A binding graph connects semantic values to views and controls. Each binding has:

- a stable ID;
- a source entity and property;
- a target view and property;
- an optional forward transform;
- an optional supported inverse transform;
- validation rules;
- display formatting.

Bindings update synchronously inside one world transaction. The binding graph rejects dependency cycles before a transaction commits.

### Widget containers

A widget is a layout container for native Mathburst views and controls. A widget can contain equations, graphs, geometry, matrices, sliders, tables, labels, outputs, and animation tracks.

Specialized widgets such as Tiny Transformer remain supported. They must expose their internal variables, bindings, views, and controls through the inspector and WebMCP. A widget is not an opaque iframe and does not run generated code.

### Operations and history

Every edit becomes an atomic world action. An action can include:

- semantic entity changes;
- binding changes;
- view changes;
- geometry primitive changes;
- selection changes;
- animation changes;
- camera changes.

Undo and redo restore the full transaction. Human edits, WebMCP calls, timeline edits, and direct manipulation use the same reducer and history model.

## Bidirectional editing

### Deterministic edits

A named visual handle maps to a known semantic operation.

For `y = a(x-h)^2+k`:

- dragging the vertex changes `h` and `k`;
- dragging a curvature handle changes `a`;
- editing `a`, `h`, or `k` moves the handles;
- editing the symbolic equation rebuilds the compatible handles.

The graph analysis layer shows only features that exist. For example, `y=x^2+1` has no real root handles.

### Ambiguous graph edits

An arbitrary drag on a graph can be underdetermined. Mathburst must not silently invent an equation. It shows two or three candidate edits, such as:

- move the vertex;
- change curvature;
- fit the current model family through the point.

Each candidate shows a live equation and graph preview. The user selects one candidate before Mathburst commits the action.

### Geometry edits

Geometry primitives have one of three states:

- **free:** the user can drag the primitive and edit its coordinates;
- **constrained:** the user can drag it only on its permitted locus;
- **derived:** the primitive is locked and computed from parent primitives.

The inspector shows the state, coordinates, parents, and defining rule. A user can explicitly detach a derived primitive, which converts it to a free primitive in one undoable action.

## Global interaction model

Input priority must remain consistent across all widgets:

1. Right-drag pans the world in every tool mode.
2. Pen and highlighter modes capture drawing input above every object.
3. A stroke can start inside a widget, cross its boundary, and continue outside it.
4. Select mode sends input to widget controls and semantic handles.
5. Double-click starts inline editing for editable text, equations, labels, and matrix cells.
6. Escape exits the current edit or construction mode.
7. Undo and redo operate on complete semantic transactions.

Ink remains an independent world object. The inspector can optionally attach selected ink to another object so that both move together.

## Progressive inspector

The default canvas remains minimal.

- Selecting an object reveals its semantic handles.
- A compact bottom inspector appears with the most important fields.
- The inspector can expand into tabs for Values, Structure, Constraints, Style, Bindings, and Animation.
- Inline value chips support fast numerical edits.
- Native browser number steppers are hidden. Mathburst uses compact fields and small increment controls.
- The inspector shows whether a value is free, constrained, derived, or computed.
- The inspector shows linked views and dependent objects.

## Native creation tools

Every creation tool uses the same flow: select the tool, click or drag on the world, create an empty object, and open its contextual controls.

### Text

- Create an empty text box with an active caret.
- Support reliable double-click editing.
- Support font size, color, alignment, width, and presentation style.
- Support inline mathematical spans linked to semantic expressions.

### Equation

- Create an empty equation field with an active caret.
- Provide a visual symbol palette and raw LaTeX mode.
- Show a rendered preview while editing.
- Detect named parameters and offer optional controls.
- Link the equation view to an existing semantic expression or create a new expression.

### Graph

- Create an empty coordinate plane.
- Create a new semantic expression or link an existing one.
- Support domains, axes, grid, colors, parameters, tables, derivatives, integrals, and feature analysis.
- Show valid roots, extrema, intersections, asymptotes, and inflection points.
- Support deterministic semantic handles and ambiguous-edit previews.

### Geometry

- Create an empty geometry-canvas object.
- Open a GeoGebra-style contextual tool menu.
- Support points, segments, lines, rays, vectors, circles, arcs, angles, triangles, rectangles, polygons, regular polygons, intersections, midpoints, perpendiculars, parallels, loci, transformations, and constraints.
- Keep every internal primitive addressable by ID.
- Support coordinates, labels, styles, direct manipulation, and dependency inspection.
- Create templates only when the user explicitly chooses one.

### Matrix

- Ask for matrix dimensions before creation.
- Create an empty editable cell grid.
- Support matrix and vector bindings, basis vectors, determinant, multiplication, eigenvalue display, and geometric transformation views.
- Keep cell edits and draggable vectors synchronized when a supported inverse exists.

### Shape

Shape is a visual annotation tool, not a mathematical construction tool.

- Support rectangle, ellipse, triangle, polygon, and freeform path.
- Support fill, stroke, opacity, corner radius, and editable nodes.
- Create the selected shape instead of always spawning a rectangle.

### Image, frame, and arrow

- Keep the current image file picker.
- Add cropping, opacity, alt text, and replacement controls.
- Keep frames as organizational containers.
- Let arrows act as annotations or visible dependency connectors.

## WebMCP design

Full behavioral coverage is more important than preserving the previous count of 18 tools. The tool count can increase.

### Common tools

- inspect the current project, scene, selection, history, entities, views, bindings, and dependencies;
- create, update, transform, style, arrange, group, and delete objects;
- apply an atomic operation batch;
- undo or redo;
- set, save, restore, and fit the camera.

### Expression and graph tools

- create or update an expression;
- add equation, graph, table, derivative, integral, and parameter views;
- bind parameters and controls;
- analyze graph features;
- create or update semantic handles.

### Geometry tools

- create an empty geometry canvas;
- add, update, style, or remove primitives;
- add constraints and transformations;
- inspect derived dependencies;
- detach a derived primitive.

### Widget tools

- create a widget container;
- add native controls and views;
- bind sources to targets;
- arrange widget regions;
- inspect the complete widget definition.

### Matrix and 3D tools

- create matrices, vectors, bases, transformations, 3D points, edges, faces, cameras, and section planes;
- update numerical values and linked direct-manipulation handles.

### Animation tools

- create timelines, tracks, keyframes, and playback ranges;
- draw, erase, reveal, hide, move, rotate, morph, highlight, and change parameters;
- animate the camera;
- play, pause, seek, and reset a timeline.

Each semantic tool call returns created or changed IDs and its expanded primitive operations. The WebMCP trace can show both levels.

## Animate mode

Animate mode is optional and hidden during normal whiteboarding. It opens a timeline with:

- object tracks;
- parameter tracks;
- camera tracks;
- highlight tracks;
- keyframes and easing;
- playback, seek, and reset controls.

Animations operate on semantic properties. They do not create a disconnected visual copy of the mathematics.

The motion language takes inspiration from 3Blue1Brown-style mathematical explanation:

- draw constructions in dependency order;
- transform matching parts of equations;
- preserve color meaning across representations;
- move the camera only to establish focus or scale;
- animate parameter changes continuously;
- highlight an invariant while the surrounding object changes.

Implement this as a browser-native declarative runtime. Do not add a Python or Manim rendering service during the hackathon.

### Instrumented construction

A semantic WebMCP batch can contain several native operations. During an agent replay, Mathburst stages those operations visually:

1. show the semantic tool call;
2. create primitive objects in dependency order;
3. draw connections and constraints;
4. reveal equations and calculated values;
5. settle into the final editable state.

The staging creates the appearance of construction from an empty canvas while keeping the replay short enough for a video.

### Deterministic agent replay

The later video uses a scripted list of real WebMCP calls. This is an agent choreography, not a prerecorded fake widget. The script can start from:

- an empty project and empty canvas; or
- a minimal scene shell that contains only camera, theme, and layout bounds.

All mathematical content must be created through native tools during the replay. A real agent such as ChatGPT can use the same schemas in the future.

The replay can show a compact agent-status overlay with real lifecycle events:

- WebMCP connected;
- semantic tool call started;
- primitive operations expanded;
- world transaction committed;
- animation track played.

Do not show a fake terminal or invented network traffic. The overlay reads the real replay and WebMCP trace state.

### Olympiad Geometry

The barycentric scene uses this fixed olympiad problem:

> Let `P=(x:y:z)` be an interior point of triangle `ABC`, with side lengths `a=BC`, `b=CA`, and `c=AB`. Let `Q=(a²/x:b²/y:c²/z)` be the isogonal conjugate of `P`. The cevians `AP` and `AQ` meet `BC` at `D` and `D'`. Prove `(BD/DC)(BD'/D'C)=c²/b²`, and prove the two cyclic analogues.

The construction must include:

- editable triangle vertices and side lengths;
- a draggable point with normalized barycentric coordinates;
- cevian intersections and live ratios;
- signed area coordinates;
- the derived, locked isogonal conjugate `Q=(a²/x:b²/y:c²/z)`;
- live Ceva checks;
- symbolic line, circle, and locus equations;
- the three product identities and their barycentric proof sequence.

The spiral-similarity scene uses this fixed construction problem:

> Let the lines `AC` and `BD` meet at `X`. The circumcircles `(XAB)` and `(XCD)` meet again at `S`. Prove that triangles `ASB` and `CSD` are directly similar. Thus `S` is a spiral-similarity center that maps segment `AB` to segment `CD`.

The construction must include:

- directed angles;
- circumcircles and intersections;
- spiral centers between segment pairs;
- homothety centers and ratios;
- live invariants under valid free-point drags;
- the live identities `∠ASB=∠CSD` and `SA/SC=SB/SD=AB/CD`;
- a proof sequence built from the two circumcircle dependencies.

### Simplex and Partitions

- Make free tetrahedron vertices directly draggable.
- Make the interior barycentric point directly draggable.
- Synchronize its position with four editable weights.
- Add an editable section plane and lattice denominator.
- Connect simplex lattice points to integer compositions and the Pascal-type recurrence.
- Compute Euler-product coefficients and the pentagonal recurrence.
- Compare exact partition values with the Hardy–Ramanujan asymptotic formula.
- Show Ramanujan residue classes and `p(5n+4)≡0 (mod 5)`.
- Clearly separate finite numerical checks from infinite theorems.

## Project, scene, and camera correctness

- A project world can contain only that project's object graph.
- Opening a project selects one of its own scenes and restores that scene's camera.
- Zoom and pan never change the active scene.
- Scene navigation is the only normal action that changes the active scene.
- Each scene stores its own camera.
- Fit Scene returns to a deterministic camera that shows all required content.
- Fit Selection frames the current selection without changing scenes.
- Reset restores one project and cannot change another project.
- Geometry, barycentric, and other project objects cannot leak into Gamma.

## Failure behavior

- Invalid edits remain previews and do not change saved state.
- Dependency cycles are rejected before commit.
- A failed WebMCP batch applies no operations.
- A failed agent replay stops on the failing step and keeps the last committed state.
- Unsupported inverse edits do not guess silently. Mathburst shows candidates or keeps the value locked.
- Animation changes mathematical state only when a track explicitly targets a semantic property.
- Missing graph features do not create invalid handles.
- A schema migration failure preserves the previous stored payload and offers a project reset.

## Persistence

The project library continues to store each project independently. The new schema stores:

- semantic entities;
- visible views;
- binding graph;
- widget structure;
- scene cameras;
- animation timelines;
- world history where currently supported.

Use one simple schema-version migration for the hackathon. Do not build a general migration framework.
