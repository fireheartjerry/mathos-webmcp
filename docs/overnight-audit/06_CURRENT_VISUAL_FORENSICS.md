# Current visual forensics — inherited state and final delta

The deeper inherited-state evidence is in `06_VISUAL_FORENSICS.md` and the post-build measured
audit is in `13_FINAL_VISUAL_QA.md`.

## Inherited failure pattern

- technically credible but too much inspector chrome;
- developer language visible before learner value;
- card-like panels competing with the proof;
- empty-state teaching block pushed the composer below the first viewport at common zoom levels;
- unsupported and disconnected WebMCP states were conflated;
- the evidence surface read like an evaluation dashboard;
- 32–40 px edit/remove targets missed the product's own accessibility bar.

## Final visual grammar

- warm white paper, near-black ink, hairline separators;
- Archivo for interface text, Fira Code only where code is genuinely code, KaTeX for mathematics;
- one continuous vertical proof rail rather than stacked cards;
- green is reserved for verified mathematical states;
- blue is reserved for agent teaching/transfer boundaries;
- no gradients, glass, shadows, icon bubbles, or ornamental illustration;
- one main work column plus a narrow evidence rail on wide screens;
- single-column flow below 1100 px;
- compact activity with no raw revision IDs;
- raw schemas collapsed behind “Inspect 6 page capabilities”.

## Final observations

At 1440×900 the problem, givens, a three-line checked derivation, composer, and primary actions
fit in one coherent view. At 390 px the page remains linear and readable. At a 720×450 CSS
viewport there is no horizontal overflow; the composer is reachable by ordinary vertical
scroll. Touch/edit/remove targets are at least 44 px.

The interface is intentionally quiet. The mathematics supplies the visual complexity; the shell
does not audition for a design-system carousel.
