## 1. What Mathburst is

An infinite canvas for mathematics where a student and an AI tutor edit the same
document. The tutor works through **48 WebMCP tools** the page registers with the
browser via `document.modelContext.registerTool`. The whole argument of the
submission is one sentence: **an agent edit the student cannot reverse is a demo,
not a tool.** Every claim in the copy and the film exists to support that.

Key architecture: one action kernel. A tool call and a toolbar click compile to the
same typed operations against the same world reducer (`dispatchWorldAction` in
`src/domain/world/reducer.ts`). Nothing bypasses it.

**Verified tool split** (greppable, do not restate it from memory):
- **12** carry `readOnlyHint: true` and change nothing.
- **28** commit to history — the ledger names the tool, the rail credits the author,
  one undo reverses the edit.
- **8** drive navigation, playback or history control: `set_viewport`,
  `focus_objects`, `open_project`, `open_scene`, `create_project`,
  `delete_project`, `play_timeline`, `step_history`.

There are **two** film productions in this repo. Do not mix them up.

| | Director film (legacy) | **Agent Replay film (current)** |
|---|---|---|
| Manifest | `video/film.manifest.json` | `video/film.replay.manifest.json` |
| Output dir | `video/public/film/` | `video/public/film-replay/` |
| Shots | 16 Director-driven shots | 2: `new-project`, `agent-replay` |

**Use the Agent Replay film.** The Director film is kept only because the narration
`.wav` files live under `video/public/film/narration-v3/` and the replay reuses them.

### The replay
`src/domain/replay/script.ts` is a scripted sequence of **real WebMCP tool calls**
executed through the registered tool objects, with the agent's lines shown in an
on-screen console. It is not a fake chat: every call in the console genuinely ran.
The finished console reads **"99 calls · 48 distinct tools"**.

## 5. Bugs already fixed — do not reintroduce these

Each of these shipped a **finished file with exit code 0** while being wrong. That
is why the verification in section 6 exists.

1. **Narration silently absent.** `Narration()` looked its shot up with
   `SHOTS.find(s => s.id === clip.shot)`, but since the v3 spec `clip.shot` holds the
   *clip's* id and the shot id moved to `overShot`. All 16 clips returned null. The
   builder already resolves offsets to absolute film time, so the composition uses
   `clip.offset` directly.
2. **Music bed silent for 60s.** `audio.py` built chord boundaries by mapping *raw*
   shot starts through `to_film`, which returns `None` for any shot the cut list
   starts late. Boundaries now come from the cut list's own `filmStart`.
3. **Music died at the last word.** `sidechaincompress` ends with its **shortest**
   input, so the unpadded voice chain cut the bed dead at 136.6s and left the closing
   hold in silence. The sidechain key is now `apad`-ed to film length.
4. **Blank final seconds.** The closing shot's `Sequence` was sized to the shot, but
   the film ends on the last *word*, which is later.
5. **Two red failed tool calls on camera.** `get_objects {kinds:['arrow']}` looked for
   an arrow that never existed, so `spotlight_objects` and `set_arrow` both received
   `undefined`. The learner's arrow is now created first, and `set_arrow` takes
   points **local to the arrow's bounds**, not world coordinates.
6. **The learner's handwriting was never drawn.** The script only emitted a console
   note saying the learner writes the Gamma recurrence. The replay runs in a blank
   `Pipeline` project, so `get_objects {kinds:['ink']}` read zero and the entire
   read-the-ink / mark-the-lost-sign opening silently did nothing. Fixed by a
   `writeOpeningInk` film hook that puts the real captured strokes on the canvas as a
   **human** commit before the agent reads.
7. **Layout covered the work.** `chromeInsets()` hardcoded `top: 0` and measured
   neither the agent console nor the progressive inspector. In film mode the console
   now docks right, evidence panels move left, editing chrome is hidden, and the
   insets measure both — so `focus_objects` frames into the band that is free.
8. **Panels clipped their own headings.** They were positioned with `--rail-w`, which
   is **44px** (the *collapsed* rail) while film mode renders the rail expanded. They
   sat underneath it. Now a fixed `left: 232px`.
9. **Capture clicked the screen corner.** A `display:none` element still measures, as
   an all-zero rect, which is truthy — so `rectOf`'s stability loop returned
   immediately and the driver clicked (0,0) believing it hit the target. `measure()`
   now treats a zero-area rect as absent.
10. **Agent camera moves entered undo; the learner's did not.** The human path drops
    select/viewport-only actions from history; the agent path did not. A framing shot
    could intercept the undo meant for the edit it introduced. Both paths filter now.

## 6. How to verify a render (do not trust exit codes)

`render-fast.mjs` and `.film/render-final.sh` carry checks that exist because each
of the failures above produced clean logs:

- **Duration** under 180s.
- **Loudness** in six windows across the film — catches a silent bed or a dead tail.
- **Tail pixel variance** via `signalstats` `YMAX - YMIN`. A blank tail measures
  240/240; real content measures about 6/255. Note this build of ffmpeg emits **no
  `YSTDEV`**, and an empty metric read as 0 fails a good film for the wrong reason.

Also worth doing by eye: extract frames and look at them.
```bash
ffmpeg -v error -ss 60 -i <film>.mp4 -frames:v 1 -q:v 3 -y frame.jpg
```
Check for: red `!` entries in the console (failed tool calls), truncated card
titles, panels clipped at the left, and content hidden under chrome.
